# Общая корзина витрины

`@widget/cart` владеет состоянием корзины, командами изменения количества и подпиской на полные снимки из Socket Gateway. Экземпляр один на приложение браузера; серверные приложения не разделяют персональное состояние.

Подключение выполняется в `DesktopApplication`:

```ts
@UseBindings(DesktopBindings, CartBindings)
class DesktopApplication extends Application {
  protected configure(app: ApplicationConfiguratorInterface) {
    app.initializers([SessionInitializer]);
    app.states([SessionState, CartApplicationState]);
    app.providers([CartApplicationProvider]);
  }
}
```

`CartApplicationProvider.prepare` удерживает CartWidget через штатный WidgetPreloader. Внутренний CartProvider загружает корзину после инициализации сессии и активирует socket/session subscriptions. Runtime достигает ready после подготовки виджета. На SSR используется подготовленная proxy сессия и выполняется один GET корзины; CartApplicationState передаёт публичный снимок вместе со страницей. Браузер восстанавливает его до провайдеров, поэтому повторного startup GET нет.

Модули внедряют только `CartWidgetServiceInterface` через публичный фасад:

- `getSnapshot()` и `subscribe(listener)` — единый Cart, состояние загрузки, busy, активная позиция, направление pendingAction и ошибка;
- `setQuantity(recordUuid, quantity, signal)` — желаемое количество; ноль удаляет позицию. Сервис сам выбирает add/change/remove и дожидается сокетного подтверждения. Результат команды не раскрывает внутренние версии и подтверждения backend.

В React `useApplicationState(CartApplicationState)` читает готовый серверный снимок, затем подписывается на общий store браузерного приложения. Для команды страница ожидает `useReadyApplication()` и получает `CartWidgetServiceInterface` из приложения. Счётчики и доступность присутствуют уже в SSR-разметке; переходной надписи, splash и отключения на время bootstrap нет.

Команда без внешнего AbortSignal живёт до завершения или смены сессии/остановки приложения; уход со страницы её не отменяет. Модули не создают свой store/hub/provider и не загружают Cart в loader. Визуальный WidgetHost не требуется: widget token и его lifecycle остаются внутри пакета.

`busy`, `activeRecordUuid` и `pendingAction` показывают ожидание в нажатом контроле до подтверждения версии по сокету. Подтверждённое количество остаётся видимым. Ошибка снимает ожидание и оставляет прежнее количество. CartStore не рассылает обновления через глобальную EntityRegistry: потребители разделяют один снимок, а серверные приложения разных посетителей остаются изолированы.

После записи и по socket-событиям HTTP-чтение не выполняется. Новая загрузка нужна только при старте приложения и смене сессии. Busy общий для всех потребителей; выход с одной страницы не удаляет корзину и подписку. Смена сессии отменяет старые запросы и очищает состояние. Framework освобождает подписки при остановке приложения.

Проверки из корня storefront: `yarn test:storefront`, `yarn typecheck`, `yarn lint`. Тесты виджета покрывают startup/SSR, общий экземпляр, socket snapshots, команды, отмену, session isolation и cleanup.


## Контрол в шапке

`import { CartControl } from '@widget/cart/control'` подключает общий контрол с иконкой кита и счётчиком количества единиц. Нажатие открывает Popover из кита: товары, параметры, количество, суммы строк и итог `itemsTotal` из Cart. Сообщения недоступности приходят из того же снимка. В строках QuantityStepper кита размера `sm` (24 px) с `outline={true}` отображается рядом с ценой единицы (`[− 1 +] × цена`) и вызывает общий CartWidgetServiceInterface: изменение количества и удаление последней единицы не создают отдельный data flow. Состояние busy и направление синего спиннера берутся из общего snapshot; после удаления фокус возвращается в список или к закрытию пустой корзины. Прокруткой списка управляет `Scrollbar` кита; вложенной нативной области прокрутки нет. Список ограничен по высоте токеном `--numbers-320` и половиной высоты viewport; прокручивается только список, заголовок и итог остаются видимыми.

Открытие не запускает GET, не создаёт WidgetHost и не регистрирует новые providers.

UI имеет отдельный публичный entrypoint `/control`. Корневой фасад с сервисами используется при instrumentation/bootstrap и не импортирует React UI/CSS; иначе Next может вынести стили из графа страницы. Root layout только размещает CartControl. Закрытие — повторным нажатием, крестиком, Escape или кликом снаружи; ссылка товара закрывает Popover перед переходом.

Миниатюра строки использует `imageUuid` из проекции Cart, а не данные открытой карточки. HTTP gateway домена и socket hub подготавливают публичный URL существующего `/v1/files/:uuid`; `imageUrl` сохраняется в SSR-снимке. В UI используется `Image` кита, при отсутствии изображения — нейтральная заглушка. Дополнительных запросов Offer или Cart для миниатюры нет.
